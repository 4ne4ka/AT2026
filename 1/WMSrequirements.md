# 1. Введение

## Цели

Цель документа — зафиксировать требования к WMS, внедрение которой должно повысить количество обработанных единиц товара в единицу времени на складе за счёт:
- **Адресного хранения** — склад разбивается на ячейки, одна ячейка — один SKU.
- **Автоматизированного управления задачами** — система формирует задания для персонала на основе входящих документов.
- **Использования промышленных ТСД** — поддержка Wi-Fi и сканирования штрихкодов при выполнении складских операций.

Документ адресован следующим группам:
- **Заказчику** — для проверки соответствия разрабатываемой системы бизнес-потребностям.
- **Команде разработки** — для проектирования архитектуры и реализации функций.
- **Специалистам по тестированию** — для подготовки тестовых сценариев.
- **Эксплуатационному персоналу** — для понимания возможностей и ограничений системы.

## Границы применения

Система WMS автоматизирует складские процессы на складах с адресным хранением. В область применения входят:
- **Приход** — обработка приходных накладных, автоматическое определение ячейки размещения, сканирование товара и ячейки грузчиком.
- **Размещение** — адресное хранение, при котором одна ячейка используется для одного SKU.
- **Расход** — обработка расходных накладных, формирование задач на отбор, сканирование и подтверждение операций.
- **Перемещение** — внутреннее перемещение товара между ячейками.
- **Сборка** — комплектация заказов по расходным документам.
- **Отгрузка** — передача товара получателю.
- **Управление задачами** — автоматическое создание задач для персонала на основе входящих документов.
- **Администрирование** — управление учётными записями, настройками системы и правами доступа.

В документ не входят:
- **Бухгалтерский и налоговый учёт** — не является предметом WMS.
- **Автоматизация транспорта и робототехники** — не рассматривается в данной версии.
- **Внутреннее проектирование базы данных и алгоритмов** — кроме внешне наблюдаемого поведения.
- **Выбор конкретных моделей серверного оборудования, СУБД и каналов связи** — в документе конкретные технологии навязываются только предметной областью.

| **Размещение** | Определение ячейки для хранения поступившего товара |
| **Расход** | Операция выбытия товара со склада |
| **Перемещение** | Внутреннее перемещение товара между ячейками |
| **Сборка** | Комплектация заказов по расходным документам |
| **Отгрузка** | Передача товара получателю |
| **Задача** | Автоматически сформированное задание для грузчика |
| **Администратор** | Пользователь, управляющий учётными записями и правами доступа |
| **Оператор** | Пользователь, вводящий первичные документы |

# 2. Общее описание

## Описание изделия

### Интерфейсы системы
- **Источник входящих документов** — оператор; конкретный способ поступления документов подлежит уточнению.

### Интерфейсы пользователя
- **Интерфейс администратора** — панель управления учётными записями, ролями, правами доступа, настройками системы; работа с накладными не предусмотрена.
- **Интерфейс оператора** — веб-форма для загрузки и просмотра накладных, фильтрации по статусу; доступ только к первичным документам.
- **Интерфейс грузчика** — приложение на ТСД с крупными кнопками и простым интерфейсом; ввод — сканирование штрихкодов.

### Интерфейсы аппаратных средств ЭВМ
- **Промышленные ТСД** — поддержка Wi-Fi и сканирования штрихкодов.
- **Сервер приложений** — размещение WMS и обработка данных.
- **Рабочие станции операторов** — доступ к веб-интерфейсу.
- **Сетевые точки доступа Wi-Fi** — покрытие склада для работы ТСД.

### Интерфейсы программного обеспечения
- **СУБД** — хранение данных WMS.
- **Операционная система ТСД** — среда работы мобильного приложения.
- **Веб-браузер** — доступ к интерфейсам администратора и оператора.

### Интерфейсы коммуникаций
- **Беспроводная сеть Wi-Fi** — основная среда связи с ТСД.
- **Сетевые протоколы** — базовый обмен данными.
- **Защищённые протоколы передачи данных** — защита обмена.

### Ограничения памяти
- **ТСД** — объём оперативной и постоянной памяти ограничен.
- **WMS** — должна обеспечивать работу в условиях ограниченных ресурсов мобильных устройств.
- **Серверная память** — требования уточняются на этапе проектирования.

### Действия

- **Нормальные и специальные действия, необходимые пользователям** — работа в сменах; приход, размещение, расход, перемещение, сборка, отгрузка; обработка исключительных ситуаций.
- **Различные способы действий в организации пользователя** — операции, инициируемые оператором (ввод документов) и грузчиком (сканирование и подтверждение задач).
- **Периоды диалоговых действий и периоды действий, оставленных без отклика** — сеансы работы оператора с веб-интерфейсом и грузчика с ТСД; конкретные значения подлежат уточнению.
- **Функции поддержки обработки данных** — ведение журналов операций и статусов задач; обработка приходных и расходных накладных; состав отчётности подлежит уточнению.
- **Действия резервного копирования и восстановления** — подлежат выяснению.

## Функции изделия

На текущем этапе зафиксированы следующие функции WMS:
- **Ведение адресного хранения** — склад разбивается на ячейки; одна ячейка — один SKU; каждая ячейка имеет уникальный машиночитаемый идентификатор.
- **Валидация входящих документов** — проверка приходных и расходных накладных.
- **Автоматическая генерация задач** — задания для грузчиков на основе входящих документов.
- **Приход** — система указывает ячейку для размещения, грузчик сканирует ячейку и товар, подтверждает действие.
- **Расход** — система указывает, что взять и куда нести, грузчик сканирует товар и ячейку, подтверждает передачу/погрузку.
- **Сборка** — комплектация заказов по расходным документам.
- **Отгрузка** — передача товара получателю.
- **Поддержка ТСД** — получение задач, сканирование штрихкодов, подтверждение операций.
- **Управление учётными записями и правами доступа** — роли и полномочия пользователей.
- **Мониторинг статусов задач** — контроль выполнения операций.
- **Обработка ошибок сканирования** — реакция на некорректные штрихкоды и исключительные ситуации.

## Характеристики пользователей

На текущем этапе зафиксированы следующие роли:

1. **Администратор**
   - **Зона ответственности** — управление учётными записями, правами доступа, настройками системы.
   - **Интерфейс** — веб-интерфейс.
   - **Требования к подготовке** — знание основ администрирования информационных систем.

2. **Оператор**
   - **Зона ответственности** — ввод первичных документов (приход/расход).
   - **Интерфейс** — веб-интерфейс.
   - **Особенности работы** — система автоматически валидирует документ и создаёт задачи.
   - **Требования к подготовке** — базовое знание складских процессов и уверенное владение ПК.

3. **Грузчик**
   - **Зона ответственности** — физические операции: приход - сканирование ячейки и товара, размещение, перемещение, сборка, отгрузка.
   - **Интерфейс** — мобильное приложение на ТСД.
   - **Требования к подготовке** — базовые навыки работы с ТСД; глубокие технические знания не требуются.

## Ограничения

На текущем этапе приняты следующие ограничения:
- **Одна ячейка — один SKU** — одна ячейка хранения предназначена для одного типа товара.
- **Уникальный идентификатор ячейки** — каждая ячейка должна иметь уникальный машиночитаемый идентификатор.
- **Использование ТСД** — для работы грузчиков применяются промышленные ТСД с поддержкой Wi-Fi и сканирования штрихкодов.
- **Покрытие Wi-Fi** — склад должен иметь покрытие Wi-Fi, достаточное для работы ТСД.
- **Отсутствие робототехники** — система не рассматривает автоматические транспортные средства и роботизированные системы.
- **Уточнение оборудования** — требования к конкретным моделям оборудования, СУБД и каналам связи уточняются отдельно.

## Предположения и зависимости

На текущем этапе приняты следующие предположения и зависимости:
- **Стабильная сеть Wi-Fi** — на складе доступна стабильная сеть Wi-Fi.
- **Наличие ТСД** — имеются ТСД с поддержкой сканирования штрихкодов.
- **Формат накладных** — оператор предоставляет накладные в согласованном формате.
- **Корректные штрихкоды** — штрихкоды на товарах и ячейках корректны и читаемы.
- **Обучение персонала** — персонал обучен работе с WMS и ТСД.
- **Серверная инфраструктура** — доступна и соответствует требованиям.
- **Пересмотр требований** — при изменении этих предположений требования могут быть пересмотрены.
