# 1. Введение
[Обзор всего документа SRS.]

## Цели
Целью разрабатываемой системы является автоматизация и наведение порядка в деятельности по заключению различных договоров (включая приходные и расходные) на предприятии. 
Внедрение системы предназначено для обеспечения проведения согласования договоров в строгом соответствии с установленным регламентом, сокращения времени, затрачиваемого на работу с договорами и прозрачности процесса электронного документооборота.

## Термины и аббревиатуры
| Термин | Определение |
| :--- | :--- |
| **Договор** | Документ, заключение которого регламентировано на предприятии и подлежит согласованию в соответствии с установленным порядком. В системе классифицируются на приходные и расходные. |
| **Инициатор** | Сотрудник предприятия, который инициирует процесс заключения договора: загружает текст, выбирает тип и маршрут согласования, обрабатывает замечания при несогласовании. |
| **Согласующий** | Сотрудник предприятия, включенный в маршрут согласования. Изучает документ и выносит вердикт. |
| **Маршрут согласования** | Упорядоченный список сотрудников предприятия, которые должны обработать документ. |
| **Круг согласования** | Один полный цикл прохождения документа по маршруту согласования. |
| **Последовательное согласование** | Вид согласования, при котором каждый следующий согласующий получает документ только после обработки предыдущим. |
| **Параллельное согласование** | Вид согласования, при котором все согласующие получают документ одновременно. |
| **Вердикт** | Решение согласующего по документу. Принимает два значения: «согласовано» (комментарий не обязателен) или «не согласовано» (комментарий или причина обязательны). |
| **Согласованный договор** | Договор, получивший вердикт «согласовано» от всех участников маршрута. |
| **Несогласование** | Ситуация, при которой хотя бы один участник вынес вердикт «не согласовано». Текущий круг завершается, документ снимается с остальных участников и возвращается инициатору. |
| **Регламент** | Установленный на предприятии порядок заключения договоров, которому должна строго соответствовать работа системы. |
| **Кадровая база** | Внешняя информационная система предприятия с данными о сотрудниках. Используется для выбора сотрудников при составлении маршрута. |

# 2. Общее описание

## Описание изделия
Разрабатываемое ПО представляет собой корпоративную систему автоматизации согласования договоров. 

* **Интерфейсы системы**: подлежат выяснению.
* **Интерфейсы пользователя**: Система должна предоставлять интерфейс, позволяющий инициаторам создавать текст договора в соотвествии с требованиями и набирать маршрут согласования, а согласующим — изучать документ и выносить вердикты.
* **Интерфейсы аппаратных средств ЭВМ**: подлежат выяснению.
* **Интерфейсы программного обеспечения**: В системе должна быть предусмотрена программная интеграция с кадровой базой предприятия для обеспечения возможности выбора сотрудников при составлении маршрута согласования.
* **Интерфейсы коммуникаций**: подлежат выяснению.
* **Ограничения памяти**: подлежат выяснению.
* **Действия**: 
  * Создание/загрузка текста договора в систему инициатором.
  * Формирование маршрута согласования из сотрудников предприятия.
  * Маршрутизация документа по параллельной или последовательной стратегии, выбранной инициатором.
  * Сбор вердиктов («согласовано», «не согласовано») и комментариев (обязательных при вердикте «не согласовано») от сотрудников.
  * Автоматическое снятие документа с рассмотрения у остальных участников и возврат инициатору при первом отказе (вердикте «не согласовано») в цепочке.
  * Отслеживание и учет количества пройденных кругов согласования для каждого документа.

## Ограничения
В данном подразделе приводится общее описание факторов, ограничивающих выбор разработчика. Ограничения сформулированы на основе исходного описания концепции системы.

**Ограничения по видам согласования**
- Система поддерживает только два вида согласования: последовательное и параллельное. Иные виды согласования в рамках данной концепции не рассматриваются.

**Ограничения по выбору типа и маршрута согласования**
- Тип согласования выбирает инициатор при инициации документа.
- Маршрут согласования указывает инициатор.
- Маршрут согласования набирается из сотрудников предприятия.
- В системе должна быть предусмотрена интеграция с кадровой базой.

**Ограничения по вердиктам согласующих**
- Согласующий может вынести только два вердикта: «согласовано» или «не согласовано».
- При вердикте «не согласовано» комментарий или причина обязательны.
- При вердикте «согласовано» комментарий может быть добавлен, но не является обязательным.

**Ограничения по условию согласования договора**
- Договор считается согласованным только в том случае, если его согласовали все участники маршрута.

**Ограничения по обработке несогласования**
- Если хотя бы один участник вынес вердикт «не согласовано», текущий круг согласования завершается в этот момент.
- Документ снимается с согласования у остальных участников, даже если они не успели его обработать.
- После несогласования инициатор получает сообщение, изменяет документ и отправляет его на следующий круг согласования.

**Ограничения по учёту**
- Количество кругов согласования по каждому документу отслеживается системой.
